# LUNARIA stress 第四轮优化

交付覆盖原 delivery/lunaria_stress，启动器仍是 starry_demo/start_lunaria_stress.cmd。用户已确认第三轮 1280 发稳定 60 FPS。本轮容量提高到 2048，保持敌弹 8×8、图集、Alpha、移动速度、出生位置、背景和完整 HUD 不变。

## 本轮变更

- 同纹理连续敌弹使用重复描述符提交：第一颗走完整 Alpha 提交，之后仅更新 x/y 并提交。减少逐弹通用参数比较、能力分支和缓存维护。软件标记 0x103 仅在 CPU 内解释，硬件收到的操作仍为 Alpha=3，未改变硬件命令 ABI。
- 保留 READY 轮询、超时/错误返回、寄存器顺序 fence、坐标缓存一致性，以及每帧结束的完成等待和命令数量核对。下一种素材仍走完整提交。
- 压力弹去掉运行时不用的 angle/age 诊断字段，每颗从 16 字节降至 12 字节；运动保留 Q8 坐标、预计算速度。2048 发池占 24576 字节，保留原 8192 字节栈，_sp=0xf900ef50，距调试工作区另余 3248 字节。
- 设置窗口支持 64–2048，增加 1408/1536/1664/1792/1920/2048 档，可输入中间整数。默认仍为 256；B/A/MAX 使用四位数字。
- 继续全程无敌、无 WARNING、玩家自由移动开火、Boss 掉血后补满、原 HUD 信息齐全。每 16 ms 最多补 32 发，2048 档约 1024 ms 填满。

本轮保留第三轮 v13/0x000D0000 硬件和 100 MHz 时钟，bit 与图集逐字节不变。普通版交付不变。无需生成 IP 或重编硬件。

## 性能证据与限制

实际 accel_api.h 交叉编译为 RV32 后，用 Unicorn 执行同一组 1282 条命令：通用提交 119470 条指令，重复提交 49125 条指令，减少约 58.9%。逐条硬件描述符完全一致，覆盖切换到其他操作/Alpha、批次结束计数，以及队列阻塞超时和硬件错误。这是命令提交代码的指令数，不是 CPU 周期测量，也不是整帧提速比例；APB 事务、DDR 背景读写及显示开销仍存在。

优先探索区间暂定约 1400–1800 发，仅作为基于已实测1280和本轮CPU优化的工程估计。缺少板上最慢绘制数据，无法精确预测60 FPS临界点。2048容量高于这个估计区间，专供探测临界值，并非承诺2048稳定60 FPS；若2048仍稳定，说明还需进一步放开容量。

- 63169350 项压力检查通过，2048 发连续模拟 600000 ms，各档持续开火达到指定可见数量。
- 参考轨迹检查采用独立速度表和从Boss出发的直线约束；强制回收测试按完整状态匹配存活弹，验证每颗只更新一次。检查实际提交的每颗8×8敌弹及四位HUD，没有隐藏或少画敌弹。
- 2048 不射击采样：B=2048，A=2050，2108条命令，172800个sprite矩形像素；640采样与第三轮相同，为700条命令/82688像素。
- 实际 RV32 初始化10项检查、普通版808555项检查、共享加载器13项检查，以及现有Alpha定向RTL检查通过。
- 本轮未上板测量；manifest 中历史1280/60记录属于第三轮，本轮 board_tested/stable_60_fps_measured 保持 false。

## 上板验证

1. 如果板上仍是第三轮v13且素材封存完整，可直接使用原 start_lunaria_stress.cmd 加载本目录新 lunaria.elf，复用相同素材；不必重烧bit。如需干净启动，烧录本目录 ti60f225_oob.bit 后退出 Programmer，再加载。
2. Alpha保持255，先设1280复查基线，再按1408→1536→1664→1792→1920→2048递增。每档确认B达到目标并预热5秒后，启动60秒测量。
3. 分别测不射击和持续射击，并移动玩家。记录平均/最低FPS、最慢绘制时间、超预算帧、重复帧和underflow/missed/错误增量。测量时避免额外JTAG轮询暂停CPU。
4. 一旦掉帧，回到前一档，用32或64发步长细测临界点。60 FPS还需检查连续新帧、无重复帧增长，不能仅看平均FPS。

## 重建与核验

在 advanced_demo 下运行：

```powershell
python -B scripts/build_lunaria_stress.py
# 以下检查在已初始化 MSVC 的终端运行
python -B scripts/run_lunaria_stress_checks.py
python -B scripts/build_lunaria_stress.py
```

构建需现有Python/Pillow和RISC-V工具链；RV32验证优先复用系统临时目录中的Unicorn 2.1.4，缺失时首次下载。检查报告与ELF、bit及源码哈希绑定。相同bit不重复覆盖，允许Programmer只读映射文件时更新软件交付。

软件构建默认从 design/game_assets 读取共用素材，并复用本交付目录中已记录哈希的 v13 bit，不依赖旧游戏模式或本地硬件编译缓存。

如以后需要完整硬件重编，可用 build_lunaria_stress.py --hardware compile；或先 --hardware prepare，在 Efinity 打开 output/game_hardware_v13/ti60f225_oob.xml 完整 Compile，再 --hardware package。准备命令会从现有源码、IP 和 BSP 建立完整 v13 工程。脚本检查输入哈希、最终时序和 bit 来源。
