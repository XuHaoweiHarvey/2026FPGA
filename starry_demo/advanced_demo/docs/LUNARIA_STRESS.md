# LUNARIA v12 压力测试：第二轮性能优化

仍使用 starry_demo/start_lunaria_stress.cmd 和 advanced_demo/delivery/lunaria_stress。本轮没有新增工程文件、交付文件名或启动器，覆盖已有压力版文件。普通版交付内容不变；共享源码的固件改动由 LN_STRESS_TEST 隔离，默认构建的可执行指令已与普通版交付 ELF 逐条比对一致。

历史实板参考：用户测得旧压力版 610 发稳定 60 FPS，640 发约 30 FPS，尚无最慢绘制和超预算帧数据。60→30 符合略超一帧预算后错过刷新边界的可能表现，但未据此认定唯一瓶颈。新版本尚未上板，不能把历史结果或模拟结果标记为本轮稳定上限。

## 本轮优化

- 压力版容量从 640 增至 832，默认仍为 256，可输入 64–832 的整数；界面、加载器参数校验、固件容量同时更新。
- 敌弹绘制矩形从 16×16 压紧为 12×12，去掉外围全透明留白。不是降低高光或缩小可见主体：新图块与原图 (2,2)-(14,14) 区域逐像素一致。四种目标 x 余数、四档全局 Alpha 的合成结果保持一致。
- 只重新打包压力版 atlas.argb 和对应清单/校验值，普通图集、背景和其他素材保持。新 ELF 的素材哈希与新图集匹配。
- 直线弹在出生时预计算每步 x/y 增量；后续只加法更新，不再逐弹逐步执行三角函数及 64 位乘除。保留原定点舍入结果与飞行速度。
- 存活子弹连续存放，分配使用尾部空位，回收用末尾子弹补位，均为 O(1)。交换后的弹在同一 tick 正好更新一次；渲染只遍历存活区。
- 缓存存活数；压力版保证全部存活弹在可见区域，因此活动/可见统计不再反复扫描整个弹池。仍通过独立全池扫描和坐标检查核对这一约束。
- 压力弹始终完全位于视口内，走专用绘制路径，省去通用裁剪分支。任意整数像素坐标仍保留，没有重新引入四像素跳格。
- 复用现有 100 MHz v12 bit，未改 RTL、CPU/DDR 时钟或资源配置。本轮先降低每颗弹的成本，便于上板确定新的稳定上限。

## 保留的行为

- 加载后直接战斗，无 WARNING、阶段切换或结束演出，全程强制无敌。
- Boss 位于 (320,128)，只从自身位置向下方扇形区域发出直线圆弹，不含激光/追踪/复杂弹型。每逻辑步最多补发 32 发，832 档约 416 ms 填满。屏外前回收并从 Boss 补发。
- 玩家 WASD/方向键移动、空格/Ctrl 射击，按住射击慢移。Boss 正常掉血、加分，空血立即补满，不清弹。
- 原版 HUD 保留：FPS、B 当前/峰值、A 当前/峰值、MAX、INV、生命、分数和 Boss 血条，阶段名 STRESS。B 是可见敌弹数；A 还包含玩家、Boss、玩家弹及特效，不等于 GPU 命令数。
- P 暂停；60 秒测量期间只屏蔽暂停，仍可移动开火。设置在测量期间锁定，应用新上限会重建弹幕并重置峰值。

## 上板验证

1. 关闭占用 JTAG 的程序，用 Programmer 重新配置本目录 ti60f225_oob.bit 后退出 Programmer。硬件内容虽相同，本轮压力图集已改变，必须清除旧封存素材及缓存后再加载。
2. 打开原 start_lunaria_stress.cmd，选择本目录 lunaria.elf 和正确串口，加载并等待素材校验完成。不要混用上一轮 ELF/atlas，也不要从普通版目录选素材。
3. 先设 610，再设 640，分别确认 B 稳定达到目标。Alpha 保持 255；每次应用后至少预热 5 秒，再启动 60 秒测量。
4. 如果 640 稳定，再按 704→768→832 逐档测试；允许输入中间整数细查临界值。每档分别不射击、持续射击测量，记录操作条件。
5. 关注平均/最低秒窗 FPS、最慢绘制、超预算帧、重复帧和 underflow/missed/硬件错误增量。平均接近 60 FPS 还不够，要检查是否连续呈现新帧。若降到 30 FPS，优先记录绘制时间与重复帧，再回退一档。
6. 832 是容量和可生成的负载，不是已经测得的 60 FPS 上限。本轮效果和新的稳定上限需由实板结果确认。

## 验证结果

- 28959586 项压力 C 检查通过；64/65/128/256/384/512/610/640/704/768/832 各档达到对应可见敌弹数，832 档连续模拟 600000 ms。
- 验证逐弹预计算结果、存活区/计数一致、回收交换正好更新一次、出生点、无敌、开火掉血与补满、容量降低、暂停和重启。
- 640 发、不射击采样：B=640、A=642、695 条命令；sprite 纹理处理像素 203648→131968，减少约 35.2%。单个敌弹矩形像素 256→144，减少 43.75%。
- 832 发、不射击采样：B=832、A=834、887 条命令、159616 个 sprite 纹理像素，仍少于旧版 640 发的 203648。背景复制量不变；这些数字不等于整帧时延或实际 DDR 流量下降幅度。
- 现有 Alpha RTL 定向仿真：同源热缓存，16×16 为 721 周期，12×12 为 478 周期，减少约 33.7%；通过四种目标 x 余数、Alpha、精确像素、缓存、反压、跨页、错误和复位检查。仿真总线延迟模型不是板上 DDR。
- 新图块与原可见区域完全一致，GUI/加载器接受 832、拒绝 833；当前 ELF 与压力素材校验匹配。
- 普通版 808555 项 C 回归、共享加载器 13 项检查通过；默认构建指令与普通版交付一致。
- 压力 ELF 保留 8 KiB 栈，_sp=0xf900ecf0，距调试区 0xf900fc00 另余 3856 字节。
- 无新实板 FPS 数据，manifest 的 board_tested 和 stable_60_fps_measured 仍为 false，历史 610/60 与 640/30 单独记录。

## 维护

在 advanced_demo 的 MSVC 开发者终端执行：

```
python -B scripts/build_lunaria_stress.py
python -B scripts/run_lunaria_stress_checks.py
python -B scripts/build_lunaria_stress.py
```

构建与 RTL 定向检查使用临时目录，不新增持久工程文件。最后一次构建将匹配当前 ELF 的检查报告覆盖到原压力交付目录。素材打包需要 Pillow，RTL 检查使用本机既有 Icarus Verilog。
