# LUNARIA v12：弹体高光与颜色微调（2026-11-01）

本轮覆盖现有 delivery/lunaria_v12；继续使用 starry_demo/start_lunaria_v12.cmd。
没有新增交付目录或启动 cmd。硬件仍是原 100 MHz v12 bit，软件和素材需要一起更新。
用户报告此前版本数量达到 551 时稳定 60 FPS；该结果是历史参考，不能直接当作本轮新版本的实测结果。
本轮提高现有 640 档发射密度，未新增独立压力场景；未进行新的实板 FPS 验收。

## 本轮变化

- 普通敌弹保持 16×16：保留现有小光圈和 alpha 12。扩大亮色高光（圆弹从 3×3 高光框扩大为 6×6），加强青蓝、紫色、金色、玫红主体色的浓度与明暗层次；主体与高光保持不透明。五角星单颗弹体改为圆形；星形弹幕的整体构图保留。
- 环形以青蓝为主，螺旋紫色，向日葵金色，花瓣粉白；辅色按发射层变化，不再逐颗随机换色。
- 玩家弹使用独立细针纹理；激光预警为柔金色点线与淡色范围，正式激光为更深的玫红实线。激光不透明主体直径从 8 增到 28 像素，采样间距从 3 增到 12，纹理从 16×16 增到 32×32；采样之间主体最窄处仍超过原直径三倍。伤害半径从 5 增到 15 像素，包含玩家判定的余量，预警期仍无伤害。
- 背景中央压暗、边缘保留星云。Boss 光环直接烘焙在原 112×112 动画内，不增加一个全尺寸 Boss 绘制命令。
- 发射闪光为四帧 16×16 动画，沿用已有有限数量的命中特效，不加逐弹拖尾。
- 花瓣/星形/多边形每次主图案发射后约 900 ms 穿插三发金色定向弹；池容量不足则跳过，不挤占已存在的弹幕。
- 每组三次花形图案后额外停顿 800 ms；环形六次、螺旋二十四次、向日葵六十四次、幕帘/融合六次后额外停顿 400 ms。停顿只停止新主图案发射，已有弹继续移动。
- 保留阶段预警，花形下一次主发射前短促蓄光。原先密度与发射节拍因此会变化，同屏数降低不等于性能退步。
- 恢复战斗全程显示 FPS、B 当前/峰值、A 当前/峰值、MAX、旋转 SPIN、无敌 INV、阶段和玫瑰参数、总血条、生命、分数。SPIN 移到底部，避免侵占战斗区域；文本空格只移动光标，不提交空白字形命令。桌面测量功能保持。
- 开始页改为深蓝星夜面板与细线装饰，显示移动/射击/暂停操作。
- 胜利和失败页统一排版，显示分数、战斗时间、已通关阶段、剩余生命、峰值可见敌弹；无敌开启时标记 ASSISTED VOYAGE。
- 战斗时间只统计 FIGHT 状态，暂停、转场、结算等待不计入；重新开局归零。峰值敌弹沿用原统计逻辑，运行中重新配置数量会清空该峰值。

- 640 档使用 720 的发射密度系数（容量仍为 640），再按图案对称性取整。首轮环形 60→67、螺旋 15→16、玫瑰 80→88、五角构图 100→110、六角构图 120→132、幕帘 30→33、融合 15→16；向日葵受整数取整影响首轮仍为 2。其他档位不变，满池仍延迟完整图案。
- 预警移动：用户澄清为 WARNING 期间无法移动。原因是该状态在处理移动输入之前直接返回。现已提取共享移动函数，WARNING 和开场 INTRO 都可正常移动，速度、斜向归一化、按住射击慢移及屏幕边界与战斗一致。阶段预警从 500 ms 延长到 1000 ms（16 ms 步长实际 1008 ms）；进入战斗时延续移动后的坐标。预警期不发射子弹、不增加战斗时间，暂停冻结移动和预警计时。

## 交付与上板

同一目录内更新了 lunaria.elf、lunaria.map、build-info.json、atlas.argb、background.argb、assets.json、README.md 和 manifest.json；ti60f225_oob.bit 内容复用已有 v12 构建。

1. 关闭启动器及其他占用 JTAG 的程序。在 Efinity Programmer 重新配置 delivery/lunaria_v12/ti60f225_oob.bit，完成后退出 Programmer。即使此前已经加载 v12 bit，这次也建议重新配置：用于清除旧素材封存/缓存状态，避免新 ELF 搭配旧图集。
2. 双击 starry_demo/start_lunaria_v12.cmd；确认 ELF 为 advanced_demo/delivery/lunaria_v12/lunaria.elf，选择原来的串口。加载 ELF 并等待素材上传与校验完成，不要混用旧目录的 ELF 或素材。
3. 先用 256 上限观察开始页；空格/Ctrl 开始和射击，WASD/方向键移动，P 暂停。确认战斗与暂停均显示完整状态；B 是可见敌弹数，A 是逻辑场景元素数，两者都不是 GPU 绘制命令数。
4. 观察青/紫/金/玫红弹体，检查高光扩大、颜色更实、五角星弹体仍为圆形，玩家弹仍细于敌弹。在不同位置击破阶段，WARNING 期间尝试四方向、斜向移动；确认约 1 秒后进入下一阶段，位置连续。松开方向键应原地停留；按住射击加移动应保持战斗中的慢速移动，但预警期间不发弹。再验证 P 暂停能冻结准备时间。
5. 在花瓣/星形/多边形阶段短暂松开射击，留足时间观察三组完整图案、约 900 ms 后的三发金色定向弹及组间停顿。测试阶段可开启无敌。
6. 检查 CURTAIN/FUSION：柔金色点线预警约 700 ms 后成为加宽玫红实线；关闭无敌，检查新宽度对应的碰撞，预警期无伤害。
7. 通关一次并故意失败一次。检查统计、重新开始、暂停不累计战斗时间、结算不继续累计时间；胜利等待约 3 秒、失败约 0.5 秒后松开并重新按射击重开。
8. 恢复此前得到 551/60 FPS 的配置，在相同阶段、Alpha、旋转、无敌条件下测量。记录实际可见敌弹范围、平均和最低秒窗 FPS、最慢绘制、超预算/重复帧、underflow/missed/错误增量。551 是历史观察值，不是本轮必须出现的场景数量；演出留白会改变弹数分布。随后选择 640，重点测试幕帘/融合的多激光与较大弹数同时出现，以及完整八阶段。每个重点场景稳定运行后测量 60 秒；如果重复帧或错误增长，退回此前稳定档，不能将 640 宣称为稳定 60 FPS。
9. 以稳定 60 FPS、无重复帧及硬件错误增长为目标；尤其查看激光和爆炸时段。新版本尚未实板验证，不能用软件模拟结果替代该步骤。

## 维护构建

在 advanced_demo 执行：

```
python -B scripts/build_lunaria.py --prepare-assets
python -B scripts/run_lunaria_checks.py
python -B scripts/run_lunaria_loader_checks.py
python -B scripts/package_lunaria_v12.py
```

C 检查需在已初始化 MSVC 的终端执行。只有 RTL 改动时才需要重新构建 v12 硬件。本轮沿用 v12 任意整数目标 x、8 KiB 纹理行缓存与连续 AXI 写回，不回退到旧 bit。

本次只调整敌弹高光与主体 RGB、激光 RGB。现有光圈、整张图集 alpha、轮廓、背景、玩家弹、其他动画及 UI 均保持；激光宽度、碰撞、绘制步距和所有游戏逻辑不变。生成后逐像素验证了修改区域和 alpha 不变；反汇编比对仅发现素材校验值的两条立即数加载指令变化。固件重新构建是为匹配新素材校验值，继续覆盖原 v12 目录。绘制命令数与处理像素量不增加，实际 FPS 未重新上板测量。

上板更新需重新配置同目录现有 v12 bit 以清除素材缓存，再由原 start_lunaria_v12.cmd 加载新 ELF 和素材。
