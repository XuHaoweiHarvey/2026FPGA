# 中央窗口压力场景：背景与 HUD 优化版

此版本以现有 48 架敌机 / 470 发敌弹测试为对照，优化软件绘图工作量。可继续使用中央窗口 v8 bit，HDMI 输出 1920×1080@60 Hz、游戏区 640×480，动态数量仍为敌机 1–48、敌弹 1–512。当前 ELF 另可配套 v9 / v10 硬件，见 [Alpha 硬件优化与配对说明](ALPHA_HARDWARE_OPTIMIZATION.md)。

## 运行

1. 结束 IDE Debug，断开并关闭旧游戏调试窗口。
2. 双击 `start_window_stress_optimized_debug.cmd`。它自动选择 `software/interactive_demo/build/game-window640-stress-opt/survival_game.elf`。
3. 点击“连接 / 读取”，再点击“加载并运行 ELF”。若刚连接提示板上程序与所选 ELF 不一致，说明新 ELF 尚未加载。板上已有中央窗口 v8 bit 时，无需重新配置 bit。
4. 初始化完成后，状态栏会显示“背景/HUD 优化版”。输入压力敌机 `48`、压力敌弹 `470`，点击“应用压力负载”。
5. 等命令确认完成后再等 3–5 秒，点击“连续测量 60 秒”，结束后导出日志。

先用 48 / 470、子弹 Alpha 225 与旧版本比较。保持键盘发送状态、玩家操作和素材一致。然后再测 48 / 480 和 48 / 512，比较最慢绘制、最低秒窗 FPS、最大换帧间隔、重复旧帧、命令数、写 burst，以及错误增量。

旧入口 `start_window_stress_debug.cmd` 仍然加载原先的压力 ELF，可用来切回对照。原全屏和已验收窗口版本的 bit / ELF 也保留。

## 改动

- 稳定运行期间，背景只恢复游戏区相对纵坐标 72–479，恢复面积从 640×480 降为 640×408。HUD 区域保留，每帧背景恢复像素减少 15%。
- 两个物理显示缓冲区各自缓存 HUD。分数、生命等变化时更新第一行；FPS / SPR / MAX 使用同一份全局统计快照，每 250 ms 更新一次，暂停和继续会立即更新提示。快照变化后，每个缓冲区在下次使用时重画该行，避免两个缓冲区轮流显示不同采样时刻的数字。统计行仍有正常的最多约 250 ms 采样延迟；逐帧性能测量不受采样影响。
- 重开、重新应用压力数量以及从自测返回后，两个缓冲区首次使用时分别完整恢复一次，清除旧画面，包括 HUD 下方 8 像素间隔。
- 开始画面、通关 / 失败提示位于游戏区，每帧随背景恢复后重绘，避免被缓存误判而消失。
- 导出状态新增 `render_options.window_hud_cache` 标记，优化版为 `true`，便于区分两份报告。原调试邮箱和状态结构布局保持兼容。

素材、精灵尺寸、数量补充规则、Alpha / Color Key 运算与顺序保持原配置。仅使用此软件版本时，无需更换 v8 bit。另行构建的 v9 / v10 包含 Verilog 优化，不能把软件优化与硬件优化的收益混为一项。

## 验证结果与限制

本地已通过六种软件配置检查，以及 31 项调试桥 / GUI 离线测试。新增检查包括：

- 将 HUD 绘图命令还原成像素，与完整重画逐像素比较，覆盖两个缓冲区、分数 / 生命变化、暂停 / 继续和 32 位时间回绕。
- 交错使用两个缓冲区并快速改变 SPR，检查两者显示同一份统计采样，以及内容未变化时不会重复提交字体命令。
- 检查两个缓冲区首次完整恢复、后续跳过 HUD，以及重开后的恢复。
- 检查开始 / 通关 / 失败提示连续帧仍会绘制。
- 检查优化 ELF 配套 v8 / v9 / v10、OCRAM 边界、动态数量控制；在写入 RAM 前拒绝旧窗口 ELF 与 v9 / v10 的错误组合。

固定 48 / 470 的离线场景中，同一帧绘制的 Sprite 数为 520，优化前后相同；背景恢复像素从 307,200 降到 261,120。HUD 内容未变化时，字体 BLIT 从 44 次降到 0。分数或统计信息变化时仍会按需绘字，不能把此结果当作所有帧都没有字体命令。

此前软件优化版已有用户提供的实板截图：48 / 470 时平均 59.98 FPS、最低秒窗 59 FPS、最慢绘制 14.918 ms、重复旧帧 1；此前对照最慢绘制为 15.637 ms。该次报告不能证明零掉帧，也不是固定相同运动序列的严格对照。当前修正共享 HUD 采样后的 ELF 尚未实板验收，不能据此保证 512 发敌弹达到 60 FPS。本轮没有配置 FPGA 或写入 Flash。

构建入口：`scripts/build_window_stress_optimized_game.cmd`。回归入口：`scripts/run_interactive_checks.cmd`。

构建日志、测试日志与哈希记录分别位于 `output/window640_stress_opt_build.log`、`output/window640_stress_opt_software_checks.log` 和 `output/window640_stress_opt_manifest.json`。
