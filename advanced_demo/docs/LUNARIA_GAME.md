## 本次 v13 连续激光与上板步骤

激光模式保留。旧版每隔 3 像素叠画一张 16×16 小图；本版每束只提交一条硬件指令，由 FPGA 直接产生连续亮芯与渐变光晕。700 ms 预警、1800 ms 结束、三束方向及原伤害判定均保留，普通敌弹、Boss 和 HUD 素材没有改动。预警改为细的连续光线，正式激光为带白色亮芯的粉/蓝/紫光束；新激光不承诺与旧拼接像素相同。

同源对照实际运行 4000 帧：玩法状态、活动弹丸内容、所有非激光指令均一致。在 512 上限的加速/激光阶段，首次生效的三束激光由 329 条绘制指令降为 3 条；原 82560 次贴图像素混合，改为 15878 个有贡献像素，四像素 DDR 分组覆盖 17516 像素（保守分组扫描可额外触及边缘零 Alpha 像素）。新路径不读取激光贴图；按行扫描，跳过不可见区域，读写只发生在当前 Back。以上为指令与像素工作量，不能折算为板端 FPS。

**本版 ELF 必须配套 v13 bit（0x000d0000，能力位 0x0001fffb）。旧 v10/v11/v12 bit 不支持连续激光指令，加载器会在写入前拒绝混用。**

1. 关闭 IDE Debug 和调试窗口，用 Programmer 配置 `hardware/v13/ti60f225_oob.bit`，完成后退出 Programmer。
2. 重新打开本目录 `start_debug.cmd`，点击连接，再“加载并运行 ELF”。FPGA 重新配置后须重新上传素材，等待 600 块上传校验完成。
3. 读取状态确认“硬件 v13”。保持先前的子弹上限与其他设置，在“加速 / 激光”或组合阶段比较激光前后 FPS、绘制耗时，并进行连续 60 秒测量。

v13 综合、布局布线、位流生成通过，实际核心频率仍为 100 MHz；布线后 core_clk 分析上限 132.135 MHz，30 条 setup/hold 时钟关系检查通过，最小报告余量 0.026 ns。RTL 检查包括横向、纵向、正负斜向、浅角、预警、透明、屏幕裁剪、4 KiB 分界、AXI 停顿、非法参数、读写错误、复位和旧版禁用状态。未在本任务中连接板卡，稳定 60 FPS 仍待实测。

## 低弹数性能修正

本次针对 4096 扩容版的额外开销修正：前 512 个弹槽常驻片内内存，超过部分才使用 DDR 分页；每批发射优先复用低编号空槽，遍历范围限制为设置的上限，HUD 复用本帧统计，不再重复扫描整个弹池。空页读取不驱逐有效页，全部失活的 DDR 页可直接丢弃。

旧版 64 上限的花瓣场景，1000 帧累计约 678 万次弹池 DDR 字读取、84 万次写入、14246 次会话。修正后 64/128/256/512 上限、八类弹幕和旋转开关的 44800 帧检查，弹池 DDR 读写/会话均为 0；这不包含背景、纹理、Alpha 混合的硬件绘制 DDR 流量，也不证明板端达到 60 FPS。低弹数固定开销已消除，60 FPS 仍需实测每帧约 16.67 ms 的预算。

前一轮仅修正弹池时可以只重载 ELF。本轮加入 v13 连续激光硬件指令，按上面的新步骤重新配置 bit 并加载素材。素材内容本身未变。

## 怎么上板

1. 结束 IDE Debug、其他调试窗口和 Programmer。本版须先配置交付包中已编译好的 v13 bit，然后退出 Programmer。旧素材封存不会因重置 CPU 或单独重载 ELF 解除。
2. 双击工程根目录的 `start_lunaria_debug.cmd`。也可用交付目录 `output/lunaria/start_debug.cmd`。
3. 点击“连接 / 读取”。提示“板上程序与所选 ELF 不一致”时，点击“加载并运行 ELF”；加载器先检查硬件和文件，再加载 ELF，并上传背景与图集。
4. 首次共上传 600 个 4 KiB 块、2,457,600 字节。每块等待固件写 DDR 并回读校验；JTAG 上传可能需要数分钟，请等待“背景和图集已完整校验并封存”。
5. 在串口区选择板卡 UART 的 COM 口并开始发送。方向键 / WASD 移动，空格 / Ctrl 射击，P 暂停，Esc 停止电脑端键盘发送。标题页按射击开始，也可点击“星海战役”。

同一套素材已封存且完整哈希匹配时，只需重载 ELF，固件回读校验后复用素材。从星海切回飞机/压力版、更新素材、上传中断后重试，都先重新配置匹配的现有 bit。加载器不自动重置平台、不清硬件错误、不直接向 DDR 写素材。

## 子弹数量与旋转设置

调试窗口“敌弹上限 64–4096”可选 64/128/256/512/1024/2048/3072/4096，也可输入范围内任意整数，默认 256。此值限制同时存活敌弹（包含边界缓冲区内的敌弹），不是每帧固定显示数量；玩家弹、激光和特效另计。点击“应用”后，在帧边界清除当前敌弹、玩家弹和激光并重启当前弹幕，保留阶段、Boss HP、分数和生命，重置数量峰值。重开保留设置；重载 ELF 恢复默认值。

较小上限降低发射频率；大于 256 时增加每批采样数。完整花瓣和星形始终整批发射，容量不足时延后。勾选“扩张时旋转花瓣 / 星形”可以边扩张边旋转，默认关闭。60 秒测量期间锁定设置。

HDMI HUD：`FPS` 为实际完成呈现的帧率；`B 当前/峰值` 为可见敌弹；`A 当前/峰值` 为敌弹、玩家弹、玩家、Boss、效果和激光；`MAX` 为存活敌弹上限。JTAG 状态读取会短暂停 CPU，窗口数据是最近一次快照；稳定帧率使用“连续测量 60 秒”验收。

## bit、ELF 和素材

- 本次增加 v13 连续激光指令及配套 RISC-V 软件、电脑绘制器。普通贴图指令保留原协议，激光版 ELF 要求 v13，核心保持 100 MHz。
- 新 ELF：`software/lunaria/build/lunaria.elf`，不覆盖原 `survival_game.elf`。
- `output/lunaria/assets.json`、`background.argb`、`atlas.argb` 与 ELF 必须配套。ELF 不嵌入 2.46 MB 图片；首次仅用 IDE 下载 ELF 会停在等待素材状态，需使用专用加载窗口。
- 实际渲染 640×480；v13 显示 1280×960 @(320,60)，HDMI 保持 1920×1080。
- Boss 112×112、敌弹/玩家/爆炸 32×32。电脑同源预览按硬件相同的两次舍入 /255 实现 source-over Alpha；光晕来自原参考纹理。
- 保留 sprite base 0x01384000 / stride 2560、background base 0x02000000 / stride 7680、源窗口 (640,300,640,480)、命令 FIFO 和安全双缓冲。
- 敌弹状态每颗 32 字节，4096 颗共 128 KiB。前 512 个槽以 16 KiB 常驻 OCRAM，其余采用分页访问。DDR 弹池保留两个帧缓冲各自偏移 `[0x10000,0x30000)` 的非显示区，1 KiB 页缓存留在 OCRAM。每页记录最新所在缓冲，换帧后只能写当前 back，允许读 front/back；绘图队列排空后才获取 CPU DDR 会话，释放后再绘图。所有外部访问均为对齐 32 位字；不写封存素材；v12 另行优化硬件素材读取缓存和写回通路。
- 当前激光版仅适用于 v13 窗口显示；不要用于全屏显示或会覆盖这些非显示行的其他程序。CPU 生成网表为 DBusSimplePlugin，无数据缓存。
- 激光 opcode=4，x/y/w/h 为四像素对齐的裁剪矩形，src 的低/高 16 位是有符号 Q14 法向量 nx/ny，stride 是矩形左上角的有符号 Q14 距离，color 为 ARGB。启动时锁存参数，不把 src/stride 当作纹理地址；目标范围和 4 KiB 分界仍检查。距离每四像素加 4×nx、每行加 ny，只对光束可见段读取 Back 并 Alpha 混合。半径 8 像素光晕与半径 2 像素预警使用共同的整数亮度曲线，电脑 `lunaria_beam.h` 和硬件逐像素对照。
- 原控制邮箱布局和编号保留。本 ELF 实现命令 1/2/3/4/6/7/10，不支持原飞机自测/48-470 压力场景，专用窗口已隐藏这些入口。
- 本 ELF 的 `g_game_presentation.state`：0 标题、1 入场、2 战斗、3 预警、4 击毁、5 胜利、6 失败。
