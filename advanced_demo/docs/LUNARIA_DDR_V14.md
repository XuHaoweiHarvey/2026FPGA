# v14 DDR 读写优化

本版是第一轮访存调度优化。硬件仍运行在 100 MHz，显示仍为 640×480 渲染、1280×960 输出；颜色、Alpha 舍入、光晕、连续激光和命令顺序保持一致。敌弹容量仍为 64–4096 可设置。是否达到更多元素下稳定 60 FPS，需要板上验证。

## 数据通路和本次改变

素材由电脑通过 JTAG 邮箱上传一次并封存到 DDR。运行时 CPU 更新游戏状态，经 APB 提交绘制描述符；电脑不逐帧发送画面。背景复制、贴图绘制、光晕混色和显示读取均由板上硬件访问 DDR。

旧版每段串行执行：读取贴图（缓存未命中时）→ 读取 Back → 混色 → 写 Back → 等写响应。v14 将混色结果放进两组、每组最多 32×128 bit 的片内缓冲。独立写状态机写出上一段时，主状态机可读取和混合下一段；两组都占用时停止生产，直到收到写响应释放缓冲。

同一矩形内的行/分段目标互不重叠，源由已有保护逻辑限制为不可变图集/背景或 Front，因此可安全提前读取下一段。下一条绘制命令仍须等上一条的读写全部结束，保持重叠光晕的混色顺序。最后一段写响应前不能宣告完成或交换 Front/Back。

这轮主要减少等待空隙，**没有减少正常绘制的 DDR 字节数**。现有 16 KiB 贴图缓存、显示低水位优先、写入准入、4 KiB 边界和单个在途读突发均保留。没有提高 DDR/核心时钟，没有降低光晕或分辨率。进一步扩大元素数可依据诊断结果决定透明区域跳过、贴图缓存改进、多笔在途读取或片内分块合成。

写通道有独立 watchdog，防止读通道持续进展掩盖写入停顿。出现错误/超时后保留已暴露的 VALID，排空已接受的读写事务，丢弃尚未开始写出的结果，再结束命令；平台复位清理缓冲归属和缓存有效位。

## 如何上板比较

1. 配置 `hardware/v14/ti60f225_oob.bit`，退出 Programmer，再启动 `start_debug.cmd`，连接并加载本包 ELF 和素材。状态应显示 v14。旧 v13 完整包保留为同级 `lunaria_v13_delivery`，可用于同场景对比。
2. 使用一致的场景、旋转、Alpha、无敌设置和活动元素数。分别观察约 300、400、512 个活动元素；超过 512 后还要关注 CPU 分页流量。配置上限不等于当帧活动数，更不等于可见数。
3. 点击原有“60 秒测量”做 FPS 验收。测量期间不读 JTAG。检查最低秒窗 FPS、最慢绘制、显示重复帧、underflow/missed 和错误码。
4. 单独点击“DDR 诊断 5 秒”查看瓶颈。只在起止时暂停 CPU 锁存/读取计数，中间不访问 JTAG。其 FPS 会受起止暂停影响，不能替代 60 秒验收。窗口日志可导出计数原值。

本帧计时分别是逻辑更新+分页 flush、提交+队列背压、末尾排空、请求交换+等待交换。提交时间包括渲染期间分页所需的排空，不能直接解释成 CPU 计算时间。各阶段之间还有健康检查/发布状态等开销，不要求阶段之和等于完整 frame_us。

## 计数寄存器与解释

硬件版本 `0x000e0000`，capabilities `0x0003fffb`，新增 bit17。向 APB offset `0xE8` 写任意值，在同一个 core_clk 边沿锁存下列 21 个字；从 `0x100` 起每 4 字节读取一个只读字。读 `0xE8` 返回字数 21。锁存不清计数，不重置硬件、不发绘制命令。老版本不映射扩展。

| 索引 | 字段 | 含义 |
|---|---|---|
| 0 | cycles | 100 MHz 核心时钟累计周期 |
| 1 | commands | Alpha/激光接受命令数 |
| 2 | busy_cycles | Alpha/激光引擎忙周期 |
| 3 | source_beats | 源贴图实际返回的 128 bit 数据拍，包括错误排空 |
| 4 | destination_beats | Back 实际返回的数据拍，包括错误排空 |
| 5 | write_beats | Alpha/激光实际接受的写数据拍 |
| 6、7 | cache_hits、cache_misses | 宽行缓存查询命中/未命中；未命中也包括不可缓存片段 |
| 8 | read_address_wait | 绘制 ARVALID 等待 ARREADY 的周期，包含仲裁等待 |
| 9 | read_data_wait | 引擎等待读数据但没有 RVALID 的周期 |
| 10 | write_address_wait | AWVALID 等待 AWREADY，含写入准入等待 |
| 11 | write_data_wait | WVALID 等待 WREADY |
| 12 | write_response_wait | 等待 BVALID |
| 13 | mixed_beats | 混色流水线输出的数据拍 |
| 14 | bank_wait | 生产端因下一个结果缓冲尚未释放而停在 PREP 的周期 |
| 15 | overlap_cycles | 写状态机工作期间，生产端处于 PREP/最终排空之外状态的周期；不是有效总线传输拍数 |
| 16 | swaps | 累计完成的显示交换 |
| 17 | reader_frame_beats | 显示读取当前帧内进度，每帧重置；不可取差作为累计带宽 |
| 18 | writer_throttle | 已有全局写准入节流累计周期 |
| 19、20 | underflows、missed | 已有显示欠载和安全边界错误累计数 |

累计计数按 2^32 回绕，差值使用无符号取模。cycles 约每 42.95 秒回绕一次，因此诊断限定 5 秒。各等待项在并行工作时可重叠，不能相加当作“总等待比例”。缓存命中率只覆盖可进入宽缓存查询路径的 Alpha 命令，激光没有贴图查询。

Alpha 流量 = 对应数据拍差 × 16 字节 ÷ 核心周期差对应的秒数；界面采用十进制 MB/s。它不包含背景复制、HDMI 显示读取、CPU 分页，所以不能据此断言整个 DDR 已饱和。连续激光没有贴图源读取，但仍有 Back 读写。

## 已验证与限制

- 同一受控停顿模型，32×32 子弹：冷缓存 1941→1306 周期；热缓存 1569→923；裁剪样例 1358→811。普通矩形像素、缓存命中/冲突/复位和跨页与参考一致。
- 激光样例：竖向 4800→4043，横向 7445→5652 周期；19,452 个像素完全一致，源贴图读取为零。
- 两组缓冲同时占用、AW/W/B 长时间停顿和超时、读写错误并发、异常 RLAST 排空、平台复位、计数与总线监视器一致性均有仿真覆盖。
- APB 快照有原子锁存、刷新、复位、只读保护、未对齐和旧版本关闭测试。新版加载器拒绝缺少 v14 启动兼容标记的旧 ELF；新版 ELF 同时支持 v13，便于比较。
- 100 MHz 编译与最终时序通过，30 条 setup/hold 关系均非负；分析核心 Fmax 135.520 MHz，最小报告余量 0.026 ns。该 Fmax 不代表本包提高了运行频率。
- 保留完整 8 KiB 栈，OCRAM 含栈使用 63,472 字节，调试保留区前余量 1,040 字节。栈检查是静态分析，不是板上高水位测量。
- 真实稠密画面命令回放报告：`verification/trace-v14-checks.json`。每个样例旧/新 RTL 都与 PC 的 307,200 个 RGB 像素比较，保留了相同读写数据拍数。模型使用可控的独立 AXI 读写通道，预先恢复背景，不包含 CPU 和显示竞争；周期数不能换算为板上 FPS。
- 同场景不同时间点的实际样例（数量门槛可能被整批发射越过，以下使用真实计数）：

| 活动敌弹 | 可见敌弹 | 绘制命令数（不含背景） | v13 周期 | v14 周期 | 减少 |
|---|---|---|---|---|---|
| 473 | 448 | 512 | 902,594 | 584,994 | 35.2% |
| 546 | 500 | 575 | 1,003,136 | 648,058 | 35.4% |
| 829 | 721 | 824 | 1,424,409 | 921,621 | 35.3% |

- 共享显示/绘制集成仿真：9 次交换、60 帧、1,997,600 像素检查通过；正常场景 underflow/missed 增量为零，故障注入和 CPU 调试复位保护通过。命令队列另测 9 条有序 DMA 填充、队满背压、忙时恢复和最终排空。
- 其他报告位于 `verification/`：64,000 帧 PC/分页逻辑与命令一致性、200 幅 RGB 比较、激光逻辑回归、加载器/设置界面、8 KiB 栈与资源保护等。

代理未连接、重置或烧写板卡。用户此前报告的是 v13 约 400 活动元素后可能降至 30 FPS；v14 的真实最大元素数与最低 FPS 尚待用户上板测量。
