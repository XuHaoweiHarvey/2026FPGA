## 评价与限制

最慢绘制低于 16.667 ms 预算约 6.030 ms；与用户此前同为 48 / 470 的 14.918 ms 截图相比，缩短约 28.7%。运动、碰撞和爆炸序列未固定，这不是严格相同逐帧负载的 A/B 测试。CPU 准备、换帧同步等还有耗时，不能将绘制余量直接折算成可增加的 Sprite 数。

该报告支持“此压力场景接近稳定 60 FPS，渲染耗时有明显改善”。最低秒窗 59.28 与重复旧帧计数 1 须保留，不支持“连续严格零重复”的结论。当前重复计数由显示边界数减区间完成游戏帧数计算，区间起止边界可能贡献一帧差；最大换帧间隔为 16.667 ms，单凭这一计数不能认定发生过一次由渲染超时导致的掉帧。

470 是目标敌弹数量，525 是本轮总 Sprite 峰值，均不代表已测得数量极限。该结果也不证明 512 敌弹、其他精灵尺寸或全屏 1080p 达标。

截图选择的是 `output/window640_alpha_v10/survival_game.elf`，硬件版本可读为 v10，但截图没有板端 bit / ELF 的完整哈希。`results.json` 中的候选哈希来自本机已生成配套包，不能视为板端文件已经核验。建议后续补齐原始导出日志，并重复 3 轮 60 秒检查可重复性。
